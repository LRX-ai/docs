This repository produces quarterly aggregates of Federal Election Commission (FEC) money attributed to Queen Street Analytics (QSA) newsletters. It runs two complementary pipelines that answer different questions about the same underlying transactions.

The repository is available at [https://github.com/lrx-ai/fec-newsletter-aggregation](https://github.com/lrx-ai/fec-newsletter-aggregation).

## Overview

The project builds two CSV outputs from FEC bulk data:

- **`send_quarterly.csv`**: trends in money each industry **put out**, attributed by the sender's catcode and broken down by recipient.
- **`receive_quarterly.csv`**: trends in money reaching each **policy area**, attributed by the recipient candidate's congressional committee seats and broken down by sender.

Both cover **2025Q1 through 2026Q2**. The two outputs are not two halves of one total; they attribute the same candidate money from opposite ends and must never be unioned.

## How it works

Both pipelines follow the same six stages over a normalized transaction set. They differ only in which side supplies the newsletter and which side becomes the breakdown dimension.

<Steps>
  <Step title="Extract">
    Pull source tables from Postgres into local CSV caches using `COPY`. The FEC tables carry no indexes, so server-side joins are avoided.
  </Step>
  <Step title="Normalize">
    Adapt `usa.fec_pac_to_pac` (OTH) and `usa.fec_pac_to_cand_current` (PAS2) into a common shape with columns for `source`, `sub_id`, `sender_id`, `recip_id`, `transaction_dt`, `amount`, `flow_type`, and `support_oppose`.
  </Step>
  <Step title="Deduplicate">
    Collapse exact duplicates on `SUB_ID` across sources, normalize both sides of OTH transfers to `(sender, recip)`, and fingerprint on `(sender, recip, date, amount)` to catch same-day duplicates with different `SUB_ID`s.
  </Step>
  <Step title="Attribute">
    Join to committee catcodes (send) or to congressional committee memberships via FEC CAND_ID -> bioguide -> committee -> newsletter (receive).
  </Step>
  <Step title="Fan out">
    Expand multi-newsletter catcodes and committee weights so each row carries one newsletter.
  </Step>
  <Step title="Aggregate">
    Group by quarter, newsletter, flow type, support/oppose stance, and counterparty, then sum amounts and count transactions.
  </Step>
</Steps>

### Send pipeline (`run_send.py`)

Newsletter comes from the **sender's catcode**. Sources are `usa.fec_pac_to_cand_current` plus `usa.fec_pac_to_pac`, deduplicated against each other on `SUB_ID`. Output is `out/send_quarterly.csv`.

### Receive pipeline (`run_receive.py`)

Newsletter comes from the **recipient candidate's congressional committee seats**, not a catcode, because candidates do not have one. Attribution follows three hops:

1. FEC `CAND_ID` -> bioguide via `c_github_legislators_current_person.fec`
2. bioguide -> committee code via `c_github_committee_membership_current`
3. committee -> newsletter(s) via `congress_cmte_crosswalk.csv`

Only **top-level committees** (4-character codes) are used; subcommittees are finer-grained than the newsletter scheme and would fragment attribution. Money is split evenly across each member's mapped committees, then evenly again within a committee's newsletters, so totals are additive across newsletters. Coverage is **incumbents only**: challengers, open-seat candidates, and defeated incumbents sit on no committee and are dropped.

## Setup

1. Install dependencies:

```bash
pip install -r requirements.txt
```

2. Copy the environment template and fill in your credentials:

```bash
cp .env.example .env
```

### Environment variables

| Name | Purpose |
| --- | --- |
| `POSTGRES_USER` | Postgres username for FEC extracts |
| `POSTGRES_PASSWORD` | Postgres password |
| `PGHOST` | Postgres host |
| `AZURE_OPENAI_ENDPOINT` | Azure OpenAI base URL (for enrichment) |
| `AZURE_OPENAI_KEY` | Azure OpenAI API key |
| `AZURE_OPENAI_DEPLOYMENT_CHAT` | Azure deployment name (default: `gpt-4.1`) |
| `AZURE_OPENAI_API_VERSION` | API version (default: `2024-12-01-preview`) |

## Usage

Run the main pipelines:

```bash
python run_send.py                       # money sent by each industry
python run_receive.py                    # money received by each industry
python run_send.py --refresh             # re-pull from Postgres first
python run_receive.py --refresh          # re-pull from Postgres first
python run_send.py --parquet             # also write Parquet output
python run_receive.py --parquet          # also write Parquet output
```

Run tests:

```bash
python -m pytest tests/
```

Regenerate the transaction type map:

```bash
python tools/build_transaction_map.py
```

Enrich the crosswalk with Azure OpenAI:

```bash
python run_enrich.py --dry-run           # preview candidates, no API calls
python run_enrich.py --limit 50          # classify 50 committees (smoke test)
python run_enrich.py                     # full run
```

Upload the enriched crosswalk:

```bash
python tools/upload_enhanced_crosswalk.py --dry-run   # validate only
python tools/upload_enhanced_crosswalk.py             # write to usa.crp_l_crosswalk_enhanced
```

Build a newsletter edition for a channel:

```bash
python tools/build_edition.py --channel "Finance & Insurance"
```

## Tests

The test suite lives in `tests/` and contains 59 stage assertions against live cached data. Tests encode structural facts the pipelines silently depend on; if one fails, the source data changed shape and the pipelines need re-verification.

Run all tests after caching extracts:

```bash
python run_send.py        # warms the shared cache
python -m pytest tests/ -v
```

Key assertions include:

- `SUB_ID` is unique within each table and shared across tables (the exact dedupe key)
- No `15J` memo rows survive extraction
- PAS2 filer is always the payer and `NAME` identifies the recipient
- Direction sets (outflow, inflow, candidate-directed) are disjoint
- Receipt codes (`30K`, `31K`, `32K`) are classified as inflows, not outflows
- Send deduplication removes more than 100,000 rows across sources
- Receive weights sum to 1.0 per candidate
- Enhanced crosswalk is purely additive: CRP-attributed transactions survive unchanged

## Important caveats

- **Never sum across `flow_type`.** A direct contribution lands in the recipient's account; an independent expenditure is money spent _about_ a candidate that they never receive. `oppose` money is spent _against_ its target and is never netted against `support`.
- **Send totals are not additive across newsletters** unless `config.MULTI_NEWSLETTER` is set to `"split"`. By default, 38 catcodes map to several newsletters and each gets the full amount. Receive is already additive because it splits evenly.
- **Send sources have different spans.** `fec_pac_to_pac` covers 2025Q1 onward while PAS2 reaches back to 2023Q1. Widening the window gains quarters that contain candidate money only, which distorts trend interpretation.
- **Receive is incumbents only.** Roughly 70% of candidate dollars go to challengers and open-seat candidates who sit on no committee and are dropped.
- **Catcodes are a current snapshot.** Reclassifying a committee retroactively rewrites historical totals.
